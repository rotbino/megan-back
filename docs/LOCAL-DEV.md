# توسعهٔ لوکال / استیج آفلاین (پروفایل `local`)

این داکیومنت توضیح می‌دهد چطور بدون اینترنت (بدون MongoDB Atlas و بدون
ArvanCloud) کل استک ایمچ را روی سیستم خودتان بالا بیاورید — انگار که
لوکال شما «استیج» باشد.

## کلید واحد: `APP_PROFILE`

در `megan-back/.env`:

```dotenv
APP_PROFILE=local      # → مونگوی لوکال + فایل‌ها روی دیسک ./uploads
APP_PROFILE=cloud      # → Atlas + آروان (پیش‌فرض؛ رفتار همیشگی)
```

در پروفایل `local`:

| چه چیزی | چه می‌شود |
| --- | --- |
| `DATABASE_URL` (Atlas) | **نادیده گرفته می‌شود**؛ به‌جایش `LOCAL_DATABASE_URL` وگرنه `mongodb://127.0.0.1:27017/megan_local` |
| `STORAGE_DRIVER` | اجباراً `local` — آپلودها داخل `UPLOAD_PATH` (پیش‌فرض `./uploads` کنار پروژه) نوشته می‌شوند |
| سرو تصاویر | خود API فستیفای با `@fastify/static` از مسیر `http://localhost:4000/uploads/...` سرو می‌کند (کش یک‌ساله مثل آروان) |
| کلیدهای `ARVAN_*` | اصلاً خوانده نمی‌شوند — نیازی به اینترنت نیست |
| لاگ بوت | خط 🚀 می‌گوید «پروفایل: local» تا همیشه بدانید با کدام محیط کار می‌کنید |

مقدارهای جایگزین پروفایل local (هر دو اختیاری):

```dotenv
LOCAL_DATABASE_URL="mongodb://127.0.0.1:27017/megan_local"
LOCAL_PUBLIC_BASE_URL="http://localhost:4000"
```

## راه‌اندازی گام‌به‌گام

1. **مونگو لوکال** — یک بار نصب کنید (دانلود آفلاین/آینه‌های داخلی) و بالا بیاورید:

   ```bash
   mongod --dbpath /path/to/data --bind_ip 127.0.0.1 --port 27017
   ```

   (داکر ترجیح دارید: `docker run -d -p 27017:27017 --name imach-mongo mongo:7`)

2. **بک‌اند** — در `megan-back/.env` فقط یک خط عوض کنید:

   ```dotenv
   APP_PROFILE=local
   ```

   سپس اسکیمای مونگوی لوکال را هماهنگ و بالا بیاورید:

   ```bash
   bun install
   bun run db:push            # همان scripts/db-push.mjs → prisma db push
   bun run seed:base-data     # دسته‌ها/استان‌ها/شهرها (برای کار واقعی UI لازم است)
   bun run dev
   ```

3. **فرانت** — هیچ کلیدی لازم نیست عوض شود؛ `BACKEND_URL` پیش‌فرض
   `http://127.0.0.1:4000` است و `next.config.ts` از قبل میزبان
   `localhost`/`127.0.0.1` (هر پورتی) را برای `next/image` مجاز کرده تا
   تصاویر `http://localhost:4000/uploads/...` رندر شوند:

   ```bash
   bun install
   bun run dev
   ```

4. **کاربر ادمین اول** (مونگوی لوکال خالی است):

   ```bash
   bun run make-admin
   ```

## نکته‌ها

- **جریان معمول کار**: روزهای آنلاین با `APP_PROFILE=cloud` به دادهٔ واقعی
  وصل می‌شوید؛ وقتی اینترنت رفت، فقط همان یک خط را `local` کنید و
  ری‌استارت — بقیهٔ کد و .env دست‌نخورده می‌ماند.
- **دادهٔ لوکال ≠ دادهٔ ابری**: مونگوی لوکال از صفر شروع می‌شود؛ برای تست
  واقعی‌نما `seed:base-data` و در صورت نیاز `seed:products` را اجرا کنید.
  اگر خواستید یک نسخهٔ کامل از Atlas داشته باشید، از
  `bun run backup` (اسکریپت backup.mjs) خروجی بگیرید و در مونگوی لوکال
  ریستور کنید.
- **فایل‌های `uploads/`**: درایور local فقط برای توسعه/خودمیزبانی است؛
  پوشهٔ `uploads/` در `.gitignore` آمده تا بایت‌های محلی وارد گیت نشوند.
- **تغییر پروایدر دیسک**: اگر خواستید محل دیگری (مثلاً `/data/imach-uploads`)
  بگذارید، `UPLOAD_PATH` را در .env عوض کنید — مستقل از پروفایل.
- **برگشت به ابر**: فقط `APP_PROFILE=cloud` (یا حذف همان خط) + ری‌استارت.
  ردیف‌های File که در لوکال ساخته شده‌اند URL لوکال دارند و روی ابر
  نمایش داده نمی‌شوند — طبیعی است؛ هر محیط دادهٔ خودش را دارد.
