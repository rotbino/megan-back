## ۰. اصول طلایی پنل ادمین (هرگز عوض نمی‌شود)

1. **جدایی کامل کد ادمین** — بک‌اند: فقط فولدر `src/admin/` (زیرماژول‌های مستقل،
   کنترلرهای `admin/*`)؛ فرانت: فقط فولدر `src/app/admin/` و `src/lib/admin/`.
   هیچ فایل ادمینی بیرون از این دو فولدر ساخته نمی‌شود.
2. **احراز هویت جدا از کاربران عادی** — کالکشن `AdminUser` (نه User)؛ JWT ادمین با
   ادعای `scope: 'admin'` و راز جدا (`ADMIN_JWT_SECRET`)؛ گارد `AdminJwtAuthGuard`.
   توکن کاربر عادی هرگز به API ادمین نمی‌رسد و برعکس.
3. **بدون SEO** — صفحات ادمین `noindex` هستند؛ متادیتای سئو، JSON-LD و sitemap
   هرگز مسیر ادمین را شامل نمی‌شوند. سرعت و سادگی مهم‌تر از سئو اینجاست.
4. **همان قرارداد API** — POST JSON، پاسخ یکنواخت `{status, data|message}`،
   DTO با class-validator، پیام‌های فارسی، rate limit ریزتر روی login.
5. **عملیات ادمین همیشه لاگ می‌شود** — از فاز A5 هر mutation ادمین در
   `AdminAction` (کی/چه/کی/چه-هدفی) ثبت می‌شود؛ فازهای قبل حداقل لاگ pino دارند.
6. **UI ادمین = زیبا، تخت و سریع** — تم سفیدِ فلت و یکدست در کل سیستم: پس‌زمینه‌ها
   سفید/خیلی روشن، فقط یک خط ظریف بین منو و محتوا؛ رنگ اصلی (آبی) فقط در
   دکمه‌ها/لهجه‌ها — نه پس‌زمینه‌های بزرگ. جداول قابل جستجو/فیلتر/صفحه‌بندی؛
   فونت و زبان فارسی، RTL.
7. **محافظت داده کاربر** — رمز/هش هرگز در پاسخ برنمی‌گردد؛ غیرفعال‌سازی کاربر
   یعنی مسدود شدن ورود و پنهان شدن محتوایش از لیست‌های عمومی (نه حذف داده).

## ۱. معماری پنل ادمین

| لایه | محل | توضیح |
|---|---|---|
| بک‌اند | `src/admin/` — `AdminModule` ریشه در `app.module.ts` | زیرماژول‌های تخت: `admin-auth/`، `admin-users/`، `admin-products/`، `admin-buy-requests/`، `admin-base-data/`، `admin-dashboard/` |
| فرانت | `src/app/admin/` + `src/lib/admin/` | `(auth)/login` بدون سایدبار؛ `(dash)/` با سایدبار + گارد نشست ادمین |
| دیتابیس | کالکشن `AdminUser` (+ `AdminAction` در A5) | username یکتا + passwordHash (scrypt) |
| توکن | JWT کوتاه‌عمر (۱۲ ساعت) | بدون refresh — انقضا → لاگین مجدد (ساده و امن) |
| ورود | `POST /admin/auth/login` | نام کاربری + رمز؛ throttle ۱۰/دقیقه؛ قفل ۵ غلط/۱۵ دقیقه |

**بوت‌استرپ ادمین پیش‌فرض** (فاز A1): در `onModuleInit` سرویس admin-auth اگر
`AdminUser` با نام کاربری `ADMIN_DEFAULT_USERNAME` (پیش‌فرض `09196421264`)
وجود نداشته باشد ساخته می‌شود با رمز `ADMIN_DEFAULT_PASSWORD` (پیش‌فرض
`admin434343`) — هر دو از `.env` قابل تغییرند. فقط در صورت نبود ساخته می‌شود؛
رمز عوض‌شده کاربر هرگز بازنویسی نمی‌شود.

**مرزها:** سرویس‌های دامنه موجود (products/users/verification/…) از طریق
export سرویس خودشان مصرف می‌شوند؛ ادمین منطق دامنه را copy نمی‌کند.
