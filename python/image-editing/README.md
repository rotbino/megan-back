# ویرایش تصویر — حذف واترمارک پاسکال

حذف خودکار واترمارک پاسکال از تصاویر گالری محصول، **کاملاً با کد و بدون هیچ سرویس خارجی** (بدون API، بدون سهمیه، بدون هوش مصنوعی ابری). چون قالب واترمارک پاسکال ثابت است و فقط جای آن و مقیاسش در هر تصویر فرق می‌کند، هر تصویر در کسری از ثانیه پردازش می‌شود.

## اصل کار (v3 — مدل دوتنه)

کشف کلیدی (۱۹-۱۱): واترمارک پاسکال **دو-جوهر** است — نشانِ گوشه‌گرد با بدنهٔ روشن نیمه‌شفاف (a≈0.50, c≈247) + متن/الگوی تیره داخلش (a≈0.39, c≈55). روی زمینهٔ تیره فقط بدنه دیده می‌شود و روی زمینهٔ روشن فقط متن — مدل تک‌رنگِ سفید متن را حذف نمی‌کرد و آلفای پهن‌شده «سایهٔ تیره» می‌انداخت.

1. **تمپلیت دوتنه**: از «جفت طلایی» (دو عکس پیکسل‌یکسان با مهر در دو جای متفاوت) نقشهٔ (آلفا، رنگ) هر پیکسل با حل دو-مشاهده‌ای برآورد می‌شود — ثابت‌های تخت دو جوهر + طبقه‌بندی + لبهٔ AA با جستجوی t. فایل: `templates/buskool-golden.npz` (کلیدهای a و c و d).
2. **تشخیص**: پاسخ DoG + تطبیق «نقشهٔ تشخیص» (اثر دیداری مهر در زمینهٔ میانی: a·(c−128)) در ۱۳ مقیاس + گارد ضد تطبیق کاذب + ریزتراز ±۸px (همهٔ شیفت‌های صحیح). خروجی: مختصات، مقیاس، امتیاز، شواهد.
3. **حذف**: وارون‌سازی ترکیب آلفای رنگی — `I = a·c + (1−a)·B` ⇒ `B = (I − a·c)/(1−a)` — مستقل از زمینه. پیکسل‌های بیرون از باکس دست نمی‌خورند. نویز تقویت‌شده فقط روی جوهر پررنگ با گاوسی ملایم گرفته می‌شود.
4. **خروجی UI**: `export_template.py` همین تمپلیت را به `src/importer/buskool-template.ts` (کوانتیزهٔ base64) صادر می‌کند تا همان الگوریتم با پورت TypeScript در بک‌اند (versl — بدون پایتون) اجرا شود: `src/importer/buskool-wm-core.ts` + `buskool-wm.service.ts` + اندپوینت‌های wm-preview/wm-apply/wm-batch.

کیفیت روی جفت طلایی (مقایسه با نسخهٔ تمیزِ واقعی) با `selftest.py` قابل دیدن است — MAE مهر از ~۳۹ به ~۶ می‌رسد و تشخیص مجددِ تصویر پاک‌شده زیر آستانه می‌افتد.

## بهبود v4 (۱۹-۱۱ شب ۲ — گزارش مالک: «مثل پاککنی که کامل پاک نکرده»)

سه مکمل روی همان مدل دوتنه (همه در `config.json` قابل تنظیم):

1. **تراز زیرپیکسلی** (`subpixel`): بعد از ریزتراز صحیح، جستجوی پیوستهٔ مشترک (ds، dx، dy) در ±۰٫۰۱۲ مقیاس و ±۰٫۵px با گام ۰٫۲۵ — نقشه‌های (a، c) با نمونه‌برداری bilinear پیوسته از قالب مبنا ساخته می‌شوند (`tpl.sample_maps`). مهرهایی که بر اثر تغییر اندازهٔ عکس نیم‌پیکسل جابه‌جا شده‌اند کامل می‌نشینند. روی سناریوهای ترکیبی، MAE باقی‌مانده را تا ~۲٫۳ برابر کم می‌کند؛ روی تصاویر ترازِ صحیح هیچ تغییری نمی‌دهد (بی‌خطر).
2. **gain تطبیقی** (`ag_*`): بعد از پاس استاندارد، اگر جوهرِ باقی‌مانده به‌روشنی بیشتر از تمپلیت باشد (برآورد با پس‌زمینهٔ درون‌یابی‌شدهٔ کانولوشن نرمال‌شده + برازش کمترین مربعات)، تا دو پاس اضافه با همان نسبت (میراشده ۰٫۸۵) حذف می‌شود. آستانهٔ ۰٫۳۵ بالاتر از سوگیریِ برآوردگر (~۰٫۲۵ روی زمینه‌های شلوغ) است تا تصاویرِ ازقبل‌تمیز دست نخورند.
3. **دینویز قوی‌تر** (`denoise_sigma 1.3` / `denoise_above 0.25`): باقی‌ماندهٔ واقعی روی تصاویر واقعی عمدتاً نویز JPEG تقویت‌شده + خطای per-pixel تمپلیت است؛ گاوسی قوی‌تر روی جوهر پررنگ «باقی‌ماندهٔ پاککنی» را محو می‌کند (پروجکشن باقی‌مانده روی ساختار تمپلیت ~۱۵-۲۰٪ کم شد، بدون تغییر MAE جفت طلایی).

ابزار کمکی: `refine_template.py` — پالایش per-pixel تمپلیت با رگرسیون چندتصویری روی ۳۵۱ اصلِ تراز ۱:۱ (برای وقتی که خواستید تمپلیت دقیق‌تر شود؛ فعلاً کنار گذاشته شده چون روی جفت طلایی بدترش می‌کرد و تأیید بصری نشده بود — خروجی: `templates/buskool-golden-v4.npz`).

تست‌های خودکار: `selftest.py` (جفت طلایی) + هارنس سناریوهای ترکیبی (شیفت زیرپیکسل/مقیاس خارج شبکه/gain) که در تاریخچهٔ توسعه استفاده شد.

## نصب

```bash
cd megan-back/python/image-editing
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

متغیرهای محیطی به این ترتیب خوانده می‌شوند: `python/image-editing/.env` > `megan-back/.env` > متغیر محیط (فقط با مقدار معتبر — مثلاً `DATABASE_URL` محیط فقط اگر با `mongodb://` شروع شود). در عمل همان `DATABASE_URL` و کلیدهای `ARVAN_*` بک‌اند استفاده می‌شود؛ نمونهٔ جدا در `.env.example`.

## دستورها

همهٔ دستورها از داخل پوشهٔ `python/image-editing` اجرا می‌شوند.

### ۱) تست سلامت (بدون دیتابیس)

```bash
python3 selftest.py
```

جفت طلایی داخل `tests/golden-pair/` را پردازش می‌کند و چهار چیز را می‌سنجد: تشخیص قوی، کاهش خطای واقعی بعد از حذف (MAE)، تغییر‌نکردن پیکسل‌های بیرون از باکس، افت امتیاز تشخیصِ مجدد. تصویر مقایسه: `output/selftest-compare.jpg`

### ۲) یک فایل (پل اتصال UI در آینده)

```bash
python3 remove_one.py photo.jpg -o photo_clean.jpg --json
# کد خروج: 0=حذف شد | 2=واترمارک پیدا نشد | 1=خطا
```

خروجی JSON شامل `status, score, scale, x, y, w, h, evidence, ms` است — بک‌اند/فرانت می‌تواند همین را با child_process یا یک سرویس کوچک FastAPI صدا بزند.

### ۳) پیش‌نمایش انبوه (برای تأیید چشمی — بدون تغییر دیتابیس)

```bash
python3 preview_batch.py --limit 10          # ۱۰ نمونهٔ تصادفی از صف
python3 preview_batch.py --ids id1,id2       # فایل‌های مشخص
```

خروجی در `output/previews-*/`: تصویر «قبل | بعد» هر مورد + `summary.json`.

### ۴) اجرای انبوه واقعی

```bash
python3 run_batch.py --dry-run --limit 20   # تمرین: تشخیص/حذف/انکود بدون آپلود
python3 run_batch.py --limit 50             # ۵۰ فایل اول صف
python3 run_batch.py                        # کل صف (قابل ازسرگرفتن)
```

هر فایل: دانلود → تشخیص → حذف → انکود main/thumb (سقف ۵۰۰KB) → آپلود آروان با کلید نسخه‌دار → صحت‌سنجی → آپدیت ردیف `File` (`has_watermark=false` + `watermark_fixed_at`) → حذف کلید قدیمی.

- اگر واترمارک پیدا نشود، فایل **دست‌نخورده** می‌ماند و فقط با وضعیت `not_found` در گزارش می‌آید (برای بازبینی دستی).
- اجرا با `output/run-state.json` قابل ازسرگرفتن است؛ گزارش CSV: `output/run-report.csv`.

### ۵) خروجی تمپلیت برای بک‌اند (پس از هر rebuild)

```bash
python3 export_template.py   # → src/importer/buskool-template.ts
```

### ۶) ساخت دوبارهٔ تمپلیت (نادر — فقط اگر پاسکال قالب را عوض کند)

```bash
python3 build_template.py --a A.jpg --b B.jpg \
    --box-a 214,626,330,668 --box-b 96,522,204,562 \
    --out templates/buskool-golden.npz
```

جفت طلایی جدید = دو عکس پیکسل‌یکسان با مهر در دو جای متفاوت؛ باکس‌ها تقریبی (چشمی) کافی‌اند.

## پارامترهای `config.json`

| بخش | کلید | پیش‌فرض | توضیح |
|---|---|---|---|
| detect | sigma | 7.0 | سیگمای DoG (برجسته‌سازی لبهٔ واترمارک) |
| detect | scales | 0.55…1.65 | مقیاس‌های جستجوی تمپلیت |
| detect | min_score | 0.45 | حداقل همبستگی برای «تشخیص مطمئن» |
| detect | min_evidence | 5.0 | حداقل شواهد (ضد تطبیق کاذب روی زمینهٔ خالی) |
| remove | alpha_floor | 0.12 | کف (1−a) — کنترل انفجار نویز روی جوهر پررنگ |
| remove | denoise_sigma | 0.7 | گاوسی ملایم فقط روی پیکسل‌های بازسازی‌شده |
| encode | main_max_bytes | 512000 | سقف حجم فایل main (پلهٔ کیفیت پایین‌تر تا رسیدن) |
| deploy | delete_old_keys | true | حذف کلیدهای قدیمی آروان بعد از تعویض موفق |
| batch | query | Product/gallery/has_watermark | فیلتر صف پردازش |

```
image-editing/
├── wm/                    ← پکیج اصلی (قابل import در سرویس آینده)

│   ├── template.py        تمپلیت آلفا
│   ├── detect.py          تشخیص چندمقیاسی
│   ├── remove.py          وارون‌سازی آلفا
│   ├── db.py              کالکشن File (MongoDB)
│   ├── storage.py         آروان S3 + دانلود
│   └── encode.py          انکود main/thumb
├── templates/             تمپلیت ساخته‌شده (با گیت می‌آید)
├── tests/golden-pair/     جفت طلایی برای selftest
├── remove_one.py          یک فایل (UI) 
├── preview_batch.py       پیش‌نمایش بدون تغییر

├── build_template.py      ساخت دوبارهٔ تمپلیت
└── output/                خروجی‌ها (gitignore)
```

## محدودیت‌ها

- فقط واترمارک پاسکال (قالب فعلی)؛ یک مهر در هر تصویر.
- تصاویر خیلی کوچک/فشرده که واترمارک محو شده باشد ممکن است `not_found` شوند — این‌ها به‌عنوان گزارش می‌مانند و در دیتابیس دست نمی‌خورند تا دستی بازبینی شوند.
